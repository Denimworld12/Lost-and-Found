| 2026-10-03 | Added custom error `RewardTooHigh()` for `postItem` when `msg.value > type(uint128).max`.                                                                                                                                                                                                                                 | PLAN.md requires that bound but lists no error for it; `RewardTooLow` would be misleading.                                                                                                                                                                       |
| 2026-10-03 | Config bounds: `minReward` and `claimStake` must be > 0 and fit in `uint128`; `confirmWindow` must be 5 minutes to 14 days. Bounds are exposed as `MIN_CONFIRM_WINDOW`, `MAX_CONFIRM_WINDOW` and `MAX_CID_LENGTH` constants.                                                                                              | PLAN.md says "bounds checked" without numbers for the amounts. A zero deposit would make claims free to spam; `uint128` matches the packed `reward`/`stake` fields.                                                                                              |
| 2026-10-03 | `items` storage is `internal`; reads go through `getItem(id)`.                                                                                                                                                                                                                                                            | One read path for items that reverts `ItemNotFound` for unknown IDs, instead of also exposing an auto-getter that returns an empty tuple.                                                                                                                        |
| 2026-10-03 | The confirm window is locked per item at claim time: `claimItem` copies the global `confirmWindow` into `Item.claimWindow` (`uint32`, packed into slot 2), and "within window" is `claimedAt + claimWindow`. `setConfig` changes the window for new claims only. Added the `claimWindow` field to `Item`.                 | `CLAUDE.md` hard rule: later config changes must not affect existing items. With the global value an admin could shorten an owner's window or delay a finder's due payout. For a live timeout demo, the admin shortens `confirmWindow` before the claim is made. |
| 2026-10-03 | EVM target left at the solc 0.8.34 default (`osaka`).                                                                                                                                                                                                                                                                     | PLAN.md: "`evmVersion` default for Hardhat 3". Sepolia has had the Fusaka (Osaka) upgrade since October 2025.                                                                                                                                                    |
| 2026-10-03 | `itemExists(id)` checks `id == 0 \|\| id > itemCount` instead of `items[id].status == Status.None`.                                                                                                                                                                                                                       | Slither flagged the enum strict equality as `incorrect-equality` (Medium), and PLAN.md says to fix every High/Medium. IDs are assigned 1..`itemCount` and never deleted, so the check is equivalent; `Status.None = 0` stays as the default value.               |
| 2026-10-03 | Slither runs on the source file (`cd contracts && slither contracts/LostAndFound.sol`, settings in `contracts/slither.config.json`) with solc 0.8.34 from `solc-select`, instead of `slither contracts/ --hardhat-ignore-compile`.                                                                                        | crytic-compile 0.4.2 maps Hardhat 3 source names only under `project/contracts/`; our build info also has `project/test-sol/` and `project/test/mocks/`, so it fails with "Unknown file".                                                                        |
| 2026-10-03 | Accepted Slither findings: `timestamp` (Low) on the confirm-window comparison and `low-level-calls` (Informational) on `withdraw`.                                                                                                                                                                                        | The window is defined by block time (minutes-to-days scale, so a few seconds of validator drift don't matter), and pull payments need a low-level `call` that forwards gas to contract wallets such as a Safe.                                                   |

| 2026-10-03 | Solidity fuzz tests run 1,024 cases each; invariants run 256 sequences of depth 64 (`test.solidity` in `hardhat.config.ts`).                                                                                                                                                                                              | More than the 256 default for the window-edge and amount fuzzing, while keeping `pnpm check` fast.                                                                                                                                                               |

Sepolia folders hold no secrets and are needed for `ignition verify`/`status`.  |
